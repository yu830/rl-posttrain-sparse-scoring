\section*{Executive summary}
A teacher can return a compact set of scores while still materializing logits for every projected row and every vocabulary entry. This project moves row chunking ahead of the Qwen2 LM head inside the normal FSDP2 forward. Each tile produces full-vocabulary-normalized scores at Student candidate IDs and the Teacher's ordered Top-$K$; only compact outputs are retained. The adapter is opt-in and preserves the tied head, module hooks and output layout of the pinned verl Worker.\cite{verl6920pinned}

On an RTX 5070 Laptop GPU, the $N=8192$ experiment reduced PyTorch peak allocated by 81.05\% under the stated allocator fraction. A separate direct Worker-to-Student fixture matched the pinned reverse-KL loss, checked gradients and one restricted final-RMSNorm update. GitHub's CPU regression workflow passed 171 tests, with two full Trainer-runtime parity tests deselected. The result is a single-GPU experimental execution-path optimization; the time measurements are descriptive and do not establish a general speedup.

\section{The engineering problem}
Let $N$ be the number of projected model rows, $V$ the vocabulary size and $K$ the number of requested candidates per row. A dense head first creates $N\times V$ logits, although the response contains only $O(NK)$ values and IDs. Candidate-only normalization would change the contract: the consumer needs candidate logprobs normalized over the full vocabulary as well as the Teacher's own Top-$K$.

Row chunking is an established technique; the contribution here is its integration with a real Worker and its scoring and consumer interfaces. Related selected-logit implementations and per-row scoring interfaces are prior work.\cite{indexedlogits,sglang38119}

\section{Method and implementation}
\subsection{The scoring contract}
For hidden row $h_t$, LM-head weights $W$, bias $b$ and candidate $i$, the returned score is
\begin{equation}
z_{t,i}=h_t^{\mathsf T}W_i+b_i,\qquad
\log p_{t,i}=z_{t,i}-\log\!\sum_{j\in\mathcal V} e^{z_{t,j}}.
\end{equation}
The normalizer ranges over the full vocabulary. Candidate IDs are ordered and may repeat; the returned values retain that order. The Worker also returns Teacher Top-$K$ IDs over the full vocabulary, with nested offsets and valid-row order preserved.

\subsection{Bounded readout inside FSDP2}
The adapter is installed before FSDP wrapping, retaining parameter objects and the tied input/output weight. A request enters through the normal outer FSDP module call. The backbone runs once; its hidden rows are then passed through the LM head as a module in tiles of at most $B$ rows. For each tile, logits are promoted to FP32 for log-sum-exp and candidate gather, and Teacher Top-$K$ IDs are retained. Tiles are discarded without assembling a full $N\times V$ result.

The live logits tile scales with $B V$ instead of $N V$; compact outputs still scale with $NK$, and backbone, model and FSDP allocations remain. This changes allocation behavior rather than eliminating the full-vocabulary projection work. When an unbudgeted tile covers all rows, the implementation uses the native dense forward; an explicit readout budget is an estimate for that portion of the computation, not a whole-device limit.

\subsection{Padding and consumer alignment}
Candidate IDs are scattered into padded model rows with the prepared attention mask, then compact outputs are restored to valid-row order. The adapter does not add a causal shift to candidate IDs. The consumer fixture applies the response mask at the appropriate prediction positions and passes the actual Worker outputs to the pinned loss.

\section{Evaluation}
\subsection{Setup}

Inputs and candidate IDs were synthetic. For each length, four fresh processes ran Dense--Chunked--Chunked--Dense; each process performed one warmup and five measured calls. $N$ denotes projected rows.

\section{Correctness and interpretation}
At $N=8192$, all 262,144 candidate logprobs and all 8,192 ordered Teacher Top-$K$ rows matched the Dense reference exactly. Across the final matrix and chunk-size sweep, 96 saved compact outputs were reloaded and compared against same-length Dense references. The comparison includes output identity, shape and offsets.

The $N=8192$ peak-allocated decrease from 3,596.6 to 681.6 MiB is 81.05\%. It is a per-call PyTorch allocator measurement, not an estimate of total device VRAM. Under the same fraction, Dense succeeded at 8,704 rows and ran out of allocator memory at 9,216; Chunked ran at 32,768, the largest tested point. A same-length Dense correctness reference was not available for 32,768.

The synchronized timings include diagnostic hooks and return of nested outputs to CPU. At 8,192 rows, Dense p50/p95 was 570.8/599.6 ms and Chunked was 626.3/944.6 ms. Process variation and host-clock differences limit interpretation; these measurements do not establish a general latency improvement.

\subsection{Worker-to-Student validation}
In a separate two-sequence fixture, actual Dense and Chunked Worker outputs fed the pinned reverse-KL consumer. The loss, Student logits gradients, final RMSNorm gradients and one restricted AdamW update matched. The fixture used $K=8$, 25 active response-prediction rows and updates only the Student's final RMSNorm weight. An earlier scalar-loss match concealed gradient differences; aligning the conversion graph with the pinned consumer removed those differences in the recorded fixture. This is a direct integration check, not a full RL training run.

\section{Current scope and future work}
The evaluated path covers tied-head Qwen2 on one GPU with FSDP2. The next stage is to extend model coverage, support packed variable-length inputs, validate FSDP1 and multi-GPU/tensor-parallel execution, and integrate an end-to-end RL trainer. The initial selected-logit-only fusion proposal remains NO-GO for the complete scoring contract; historical negative findings remain in the project results.

The public results summary contains the matrix values, and the evidence manifest binds archived measurements to SHA-256 hashes. \section{Conclusion}
Moving the row boundary ahead of the LM head gives this Teacher Worker a smaller live readout allocation while preserving the outputs required by its consumer. The measured single-GPU result, exact output comparisons and restricted Student update provide a concrete basis for the next integration stage.
