\section*{Abstract}
Teacher scoring can return compact outputs while first materializing a much larger row-by-vocabulary logits tensor. This project integrates a row-chunked LM-head readout into a pinned verl \code{TeacherFSDPWorker}. It preserves full-vocabulary-normalized log probabilities at Student candidate IDs and the Teacher's ordered Top-$K$, while entering through the normal FSDP2 forward and retaining tied weights and module hooks.

For Qwen2.5-0.5B-Instruct in BF16 on one RTX 5070 Laptop GPU, with $K=32$, 256-row chunks, CPU offload and allocator fraction 0.50, the $N=8192$ Worker comparison reduced peak allocated by 81.05\%. All 262,144 candidate scores and 8,192 ordered Top-$K$ rows matched exactly. A separate direct Worker-to-Student fixture matched the pinned loss, checked gradients and one restricted RMSNorm update. The result is a single-GPU experimental optimization; the measured timings are descriptive.

\section{Problem and scoring contract}
Let $N$ be the number of projected model rows, $V$ the vocabulary size and $K$ the candidate width. A dense language-model head can allocate $N\times V$ logits even when the response contains only $O(NK)$ values and IDs. Reducing the response alone therefore does not bound the intermediate readout allocation.

For hidden row $h_t$, head weights $W$, bias $b$ and candidate $i$, the required full-vocabulary-normalized score is
\begin{equation}
z_{t,i}=h_t^{\mathsf T}W_i+b_i,\qquad
\log p_{t,i}=z_{t,i}-\log\!\sum_{j\in\mathcal V}e^{z_{t,j}}.
\end{equation}
The denominator covers the entire vocabulary. The Worker also returns the Teacher's own ordered Top-$K$ IDs, so projecting only Student candidate logits cannot reproduce the complete interface in general. Candidate IDs can repeat; their order and multiplicity, valid-row order and nested offsets are part of the output contract.

Row chunking and selected-logit primitives are established techniques. The engineering contribution here is their integration with the fixed Worker, FSDP lifecycle and downstream scoring contract.\cite{verl6920pinned,indexedlogits,sglang38119}

\section{Implementation}
\subsection{FSDP and the LM-head lifecycle}
The adapter is installed before wrapping the ordinary \code{Qwen2ForCausalLM}; it retains the parameter objects and the tied input/output weight. A request enters the normal outer FSDP module call. The backbone and final normalization run once, and the resulting hidden rows are passed through \code{lm_head} as a module, in tiles. This preserves the head's pre- and post-hooks as well as the outer FSDP forward boundary.

For each tile, logits are promoted to FP32 for log-sum-exp and candidate gather; the selected scores are cast back to the logits dtype and the Teacher Top-$K$ IDs are retained. The tile is discarded before the next one. The live logits tile therefore scales with $BV$ rather than $NV$ for $B<N$; compact outputs still scale with $NK$, and the model, backbone and FSDP allocations remain. Full-vocabulary projection work is not eliminated.

\subsection{Chunk selection and dense fallback}
An optional head budget selects the tile size before the forward. If $s$ is the logits element size in bytes, $H$ the requested readout budget, and $B_{\mathrm{requested}}$ the requested row cap (or $N$ if omitted), the implementation's estimate is
\begin{align}
M_c &= NK(s+8), & m_r &= \left\lceil1.25\,[V(s+8)+24K]\right\rceil,\\
B &= \min\!\left(N,B_{\mathrm{requested}},\left\lfloor\frac{H-M_c}{m_r}\right\rfloor\right).
\end{align}
The estimate includes compact outputs, a logits tile, FP32 work tensors and Top-$K$ bookkeeping; it does not bound all model allocations, backend workspaces or fragmentation. If no explicit budget is set and the selected tile covers all rows, the integration uses the native dense forward. An explicit budget does not silently select that fallback.

\subsection{Padding and consumer alignment}
Candidate IDs are scattered into padded model rows using the prepared attention mask, and returned valid rows are restored in their original order. The adapter does not add a causal shift to those IDs. In the consumer check, the response mask is aligned to prediction positions before aggregate loss and diagnostic calculations.

\section{Experimental setup}
The final comparison used Qwen2.5-0.5B-Instruct, BF16 and SDPA on one RTX 5070 Laptop GPU, with PyTorch 2.14.1+cu130, FSDP2 CPU offload, $K=32$, $B=256$ and PyTorch allocator fraction 0.50. Text and candidate IDs were synthetic. For each length, four fresh processes ran in Dense--Chunked--Chunked--Dense order. Each process had one warmup and five measured calls; each p50/p95 below summarizes ten calls per mode.

All 96 saved compact outputs from the final matrix and the chunk-size sweep were reopened and compared against same-length Dense references. At $N=8192$, all 262,144 candidate logprobs and all 8,192 ordered Teacher Top-$K$ rows matched exactly; the comparison also checked output identity, shapes and offsets.

\subsection{Timing interpretation}
The synchronized spans include diagnostic hooks and nested-output return to CPU. At 8,192 rows, Dense p50/p95 was 570.8/599.6 ms and Chunked was 626.3/944.6 ms. The small sample showed process variation and host-clock differences, so it does not establish a general latency improvement.

\section{Worker-to-Student validation}
In a separate two-sequence fixture, actual Dense and Chunked Worker outputs were passed directly to the pinned reverse-KL consumer. The fixture used $K=8$, 25 active response-prediction rows and one AdamW update restricted to the Student's final RMSNorm weight. Table~\ref{tab:student} shows selected observations; the checked Student-logits gradients and final RMSNorm gradients also matched exactly.

\section{Current scope and future work}
The measured path covers a tied-head Qwen2 model on one GPU with FSDP2; the consumer experiment is a restricted update. Future work includes packed variable-length inputs, broader model coverage, FSDP1 and multi-GPU/tensor-parallel validation, and end-to-end RL Trainer integration. The earlier selected-logit-only fusion proposal remains NO-GO for the complete Teacher contract; its negative findings remain in the historical results.

\section{Conclusion}
Moving the row boundary ahead of the LM head reduces the live readout allocation while preserving the compact scoring outputs. The measured single-GPU result, exact output comparisons and restricted Student update provide a concrete basis for further integration.
