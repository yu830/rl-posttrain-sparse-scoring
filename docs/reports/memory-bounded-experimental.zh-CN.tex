\section*{摘要}
Teacher 即使只返回紧凑分数，也可能先分配完整 token×vocabulary logits。本实现把行分块前移到 Qwen2 LM Head 之前，保留 Student 候选 ID 上的全词表归一化 logprob 和 Teacher 自身 Top-$K$。适配器在普通外层 FSDP forward 内运行，保留模块 hooks 与共享参数；无显式预算且分块覆盖全部投影行时，使用原生 dense forward 回退。受控单 GPU 实验完成 384 次直接模型调用及 64 次真实 Worker 调用，没有复现先前 CUDA abort。在 PyTorch allocator fraction 0.25 下，offload 开启的 dense 路径在 1536 行成功、2048 行 OOM，chunked 执行到 32768 行，但同长度 dense 数值校验只到 8192。fraction 0.50 下，dense 在 8704 成功、9216 失败；更高预算的 dense 参考验证了 chunked 的 9216 行输出。真实 Worker 输出还保留了固定 loss、所检梯度和一次最终 RMSNorm AdamW 更新。后续真实 Worker 在 8192 行与同预算 Dense 一致，在 9216 行与较高预算 Dense 参考一致。无人工 fraction 的 1024 行实验测量显存，并未测容量上限；完整 RL 训练和 Ray 调度仍未覆盖。

\section{问题动机与贡献边界}
蒸馏消费者所需的信息不同：指定 logits、条件概率、全词表 logprob 和 Teacher Top-$K$ 是不同契约。返回 $NK$ 个数值的接口，内部仍可能执行和分配 $NV$ 投影。其中 $N$ 为实际经过 Head 的模型行数，$V$ 为词表大小，$K$ 为候选宽度；padding 行也计入 $N$。

逐行评分接口与索引 selected-logit 原语已经处理其中部分问题。此前源码调查记录了相关 SGLang、vLLM 接口及 IndexedLogits，这些观察仍限定在当时的固定版本。\cite{sglang38119,vllm56984,indexedlogits,omnilens2026} 本报告的工程对象更具体：在固定 verl 的 Qwen2/FSDP 执行中，限制 logits tile 的分配，同时保留完整 Teacher 契约。行分块是已有方法；此前仅计算 Student 候选 logits 的融合方案，对完整契约仍为 \textbf{NO-GO}。

目标为 \href{https://github.com/verl-project/verl/tree/87cd055e872f9fdd7b976fcd797a0934b6dba265}{verl PR \#6920 的固定版本} \code{87cd055e872f9fdd7b976fcd797a0934b6dba265}。补丁显式启用，关闭时保留上游分支。源码观察及本地运行不代表上游已接受或合并。

\section{FSDP 执行与受限读出}
\subsection{模块与 hooks 生命周期}
适配器在 FSDP 包装之前安装于普通、未包装的 \code{Qwen2ForCausalLM}，保留参数对象、模块树及输入输出共享权重。评分请求经 \code{self.engine.module(...)} 进入普通外层 FSDP forward。Backbone 与最终 norm 执行一次，随后将展平 hidden rows 分块送入 \code{self.lm_head(tile)}。每块都调用模块本身，使其 pre/post hooks 仍然运行；直接读取权重作矩阵乘法会绕开该生命周期。

每个至多 $B$ 行的 tile 产生 logits，再转为 FP32 做全词表 log-sum-exp 和 candidate gather；logprob 转回 logits dtype，同时保存 Teacher Top-$K$ ID。各块及时释放，不拼接完整 logits。紧凑输出仍占 $O(NK)$；backbone hidden state、模型与 FSDP 分配仍属于完整 forward。

已验证目标为 tied-embedding Qwen2、普通 dense linear head、BF16、world size one、eval/no-grad 与无 KV cache。适配器拒绝不支持的多 rank、untied head、LoRA、量化/QAT、Liger/fused alternative forward 和 sequence parallel。存在 FP32 代码路径不等于已有 FP32 GPU 证据；FSDP1、TP 及多 GPU 仍为 \code{NOT_RUN}。

\subsection{CPU offload 与 dense fallback}
FSDP2 CPU offload 改变参数驻留，且可能主导完整 forward 时延；它不取消普通 FSDP forward 边界。受控实验直接检查 root/decoder 的 offload policy，而非仅根据命令行开关推断。

没有显式 head budget 且选中 tile 覆盖全部模型行时，走 \code{dense_full_row_fallback}：先完成原生 dense forward，再在 FSDP 返回后运行原 gather/reduction。若在参数仍驻留时归约完整 tile，峰值反而可能上升；早期 $N=512$、chunk=512 的全行 tile 使绝对峰值增加约 33.7\%，由此形成原生回退策略。任何显式 head budget 都禁用这一自动回退，避免把请求的估计预算默默替换成无界 dense 执行。错误及 OOM 向外传播，不重试外层 forward。

\subsection{预算估计及约束范围}
令 $s$ 为 logits 每元素字节数，$\gamma=1.25$ 为默认安全因子，$H$ 为请求的 head 字节预算。实现中的估计为：
\begin{align}
M_{\mathrm{compact}}&=NK(s+8),\\
m_{\mathrm{row}}&=\left\lceil\gamma\,[V(s+8)+24K]\right\rceil,\\
\widehat M(B)&=M_{\mathrm{compact}}+Bm_{\mathrm{row}},\\
B&=\min\!\left(N,B_{\mathrm{requested}},\left\lfloor\frac{H-M_{\mathrm{compact}}}{m_{\mathrm{row}}}\right\rfloor\right).
\end{align}
该式包含紧凑输出、logits tile、最多两个 FP32 词表工作张量及保守 Top-$K$ bookkeeping。若紧凑输出加一行估计都放不下，在 forward 前拒绝。预算只约束该读出估计，不覆盖完整模型、FSDP 参数驻留、碎片、其他进程及所有 CUDA workspace。全词表投影计算量仍约为 $2NVd$；缩小 tile 是分配与更多 Head 调用之间的取舍。

早期独立的 $N=1024,K=32$ FSDP2 预算 probe，在 64/128/256 MiB 预算下选出 35/70/141 行；读出 allocated 增量约为 51.03/101.75/204.64 MiB，完整 forward 峰值约 552.28 MiB。它们只校准该工作负载。Head 估计与 \code{torch.cuda.set_per_process_memory_fraction} 约束的是不同数量。

\section{负结果与证据解释}
最初 selected-logit 提案不满足全词表归一化加 Teacher Top-$K$；早期全行 chunk 增加完整峰值，推动了显式原生回退策略。首次 CUDA abort 虽未在受控集合重现，根因仍未知。Buffer cast 解释一个直接/Worker 数值差异，不能用于解释该 abort。

早期项目消费者在两个梯度分支上分别把 BF16 Student logprob 转为 FP32，标量 loss 虽与上游一致，RMSNorm 与 logits 梯度的相对 L2 差异却约为 1.07\% 和 1.80\%。按上游图结构复用同一次 FP32 转换后，该 fixture 的差异消失。保留这一负结果，是为了说明必须核对梯度和更新，不能只接受标量 loss 一致。

早期样本在 WSL 临时存储清理后丢失，没有重建成历史事实；此处引用后续有记录运行。归档矩阵曾把全行 Head 调用误标为避免完整 logits，实际形状与标签相反，当前脚本已修正。超出 Dense 参考上限的更长 Chunked 结果，数值等价仍为 \code{UNKNOWN}。退出码或有限输出不替代完整数值及训练验收。
